The data

The data in this lab come from the Wikispeedia data set published by the Stanford Network Analysis Project (SNAP). Wikispeedia was an online game in which a player was given a starting Wikipedia article and a target article. The player attempted to reach the target using only hyperlinks on the articles they visited.

The data contain a fixed, condensed version of Wikipedia with several thousand articles, over one hundred thousand directed hyperlinks, and tens of thousands of completed human navigation paths. The original data were collected and analyzed by West et al. (2009).

The following files are provided in the data folder.

articles.tsv

A one-column file containing every article in the Wikispeedia network. Article names are URL encoded. For example, spaces appear as underscores and some special characters are represented using % followed by hexadecimal digits. Lines beginning with # contain metadata rather than observations.

links.tsv

A two-column file. Each row records a directed hyperlink from source to destination. Thus, the row

Statistics    Mathematics

would mean that the Statistics article contains a hyperlink to the Mathematics article. A link in the other direction does not automatically exist.

paths_finished.tsv

Each row is one successfully completed Wikispeedia game. The important variable for this lab is path, which records the sequence of articles named in the player’s path, separated by semicolons. A < indicates that the player pressed the back button.

Reading the files

The files have metadata lines beginning with #, but do not have ordinary column headers. Useful arguments to read_tsv() are therefore comment and col_names. Missing ratings are recorded as NULL.

  • links: source, destination

  2. Verify that every source and destination appearing in links is also present in articles.
  3. For each article, calculate its in-degree, the number of hyperlinks pointing to that article, and its out-degree, the number of hyperlinks pointing from that article. Articles with no incoming or outgoing links should receive a degree of zero.
  4. Display the ten articles with the largest in-degree and the ten with the largest out-degree. Briefly describe what kinds of articles tend to appear near the top of each list.

readable_name <- function(x) {
  x |>
    URLdecode() |>
    str_replace_all("_", " ")

2. Build a random surfer

Suppose a person browses this version of Wikipedia according to the following rules.

At each step:

  1. With probability 0.15, the surfer jumps to an article chosen uniformly at random from all 4,604 articles.
  2. Otherwise, the surfer follows one outgoing hyperlink chosen uniformly at random from the current article.
  3. If the current article has no outgoing hyperlinks, the surfer must jump to a uniformly selected article.

This defines a Markov chain whose states are Wikipedia articles.

First, use split() (or another method of your choosing) to construct a list named outlinks. Each element should contain the destinations reachable in one click from a particular source article. For example, outlinks[["Statistics"]] should return a 22-element character vector containing the articles linked from Statistics.

Next, write a function

random_surfer(start, n_steps, jump_prob = 0.15)

that simulates the process. The function should return a character vector of length n_steps + 1, including the starting article as its first element. Your function should use outlinks and articles, and it should work for articles with no outgoing links.

Use set.seed(323) and simulate 25 steps beginning at Statistics. Display all 26 visited articles using readable article names.

Finally, answer: why is this process a Markov chain?

Hint

For a current article called current, outlinks[[current]] returns NULL when no outgoing links are available. The functions runif() and sample() will also be useful.

3. Estimate PageRank by simulation

The long-run fraction of time that the random surfer spends on an article is its PageRank under this model. In other words, if the surfer visits article \(j\) a total of \(N_j\) times during a long run of \(N\) steps, then

\[ \widehat{\pi}_j = \frac{N_j}{N} \]

is a Monte Carlo estimate of the “PageRank” of article \(j\).

Use set.seed(323) and simulate 251,000 steps beginning at Statistics. Discard the first 1,000 visited states before estimating PageRank. Use the first 250,000 remaining states for the analyses below.

  1. Estimate the PageRank of every article. Articles not visited after the first 1,000 states should receive an estimated PageRank of zero.
  2. Display the 15 articles with the largest estimated PageRank. Comment on what kinds of articles have the highest PageRank.

4. Is PageRank just counting links?

An article with many incoming links should tend to receive a high PageRank, but PageRank also accounts for where those links come from.

Join the PageRank from Exercise 3 to the degree summary from Exercise 1. Then:

  1. Make a scatter plot of in-degree versus PageRank. Because both variables are highly skewed, choose axis transformations that make the relationship easy to inspect.
  2. Rank articles separately by in-degree and PageRank. Hint: min_rank(desc(in_degree)) can help here. Identify five articles whose PageRank rank is substantially better than their in-degree rank, and five for which the reverse is true. Explain why this might occur.
  3. Compute the rank correlation between in-degree and PageRank.

5. Do people actually surf randomly?

PageRank describes a hypothetical random surfer. The Wikispeedia data also contain paths taken by real people, giving us a way to assess that model.

Use the code below to create a data set containing the intermediate named articles in every completed path:

human_steps <- paths |>
  mutate(game_id = row_number()) |>
  select(game_id, path) |>
  separate_longer_delim(path, delim = ";") |>
  rename(article = path) |>
  filter(article != "<") |>
  group_by(game_id) |>
  mutate(
    position = row_number(),
    n_named = n()
  ) |>
  filter(position > 1, position < n_named) |>
  ungroup()
  1. Explain what the code above does by adding comments to it in your .qmd file.

For every article, you’ve calculated the number of times it occurs as an intermediate article in a completed human path. Join these counts to the PageRank simulation from Exercise 3.

  1. Calculate the rank (Spearman) correlation between PageRank and human intermediate visit counts.
  2. Make a plot comparing PageRank rank with human-visit rank.
  3. Based on your analysis, does the random-surfer model capture anything real about how people navigate Wikipedia? Where does it fail?

Style guidelines

All assignments in this course must employ proper coding style, as outlined below:

  • All code should obey the 80 character limit per line (i.e. no code should run off the page when rendering or require scrolling). To enable a vertical line in the RStudio IDE that helps guide this, see the style guidelines from lab 0 or ask a member of the teaching team for help.

  • All commas should be followed by a space.

  • All binary operators should be surrounded by space. For example x + y is appropriate. x+y is not.

  • All pipes %>% or |> as well as ggplot layers + should be followed by a new line.

  • You should be consistent with stylistic choices, e.g. only use 1 of = vs <- and %>% vs |>

  • Your name should be at the top (in the YAML) of each document under “author:”

  • All code chunks should be named (with names that don’t have spaces, e.g. ex-1, ex-2 etc.)

  • File names in your GitHub repo such as lab-x.qmd must not be changed and left as provided. Additionally, your repo must pass certain basic checks. The results of these checks are visible on GitHub via the badges at the top of your README and the actions tab. These are meant to give you feedback around the structure and reproducibility of your repository and assignment - they do not assess the correctness of your work. You should consider them a necessary but not sufficient condition when turning in your work - passing all of the checks simply means your have met a minimum standard of reproducibility for the assignment.

Fundamentally, the check is making sure 1) you only have the files you should in your repository, 2) your .qmd renders.

If you have any questions about style, please ask a member of the teaching team.
