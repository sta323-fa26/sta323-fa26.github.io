The data

The SNP data set and population labels data set are sourced from the Novembre lab GitHub repo.

snp_pca.rds

Load the data using readRDS. The data are stored as a large matrix. Rows are individuals (observations), and columns are specific loci where SNPs (single nucleotide polymorphisms) occur. Each cell contains a 0, 1, or 2, indicating how many copies of a particular allele the individual has at that SNP site. A value of 0 means the individual is homozygous for the other allele (0 copies of the counted allele), a value of 1 means the individual is heterozygous (1 copy), and a value of 2 means the individual is homozygous for the counted allele (2 copies). Some individuals have a missing genotype at a given SNP; these are represented as NA.

population_labels.csv

This data set contains two columns: IID which contains an individuals unique ID and population which is a label that tells which population the individual belongs to.

pop_locations.csv

This data set contains three columns: Population (the population in question) and longitude, latitude which describe where the populations come from. This data was sourced from Table 1 of Hollenbach et al. (2012).

3. Plot

Using ggplot, create a scatter plot of the first two principal components and color the points by population. If any population values are missing, the legend should instead read: “Unknown” (instead of ‘NA’). In all plots you make, the title should be informative, the axes labeled (e.g. “PC1” and “PC2” here) and the background uncolored (change the theme from the default gray). Make sure the color scheme is colorblind friendly, but still clearly distinguishes meaningfully between populations.

Hint

You’ll need to do some data wrangling to join the population_labels data set to the SNP data set prior to creating the plot. Regular expressions and left_join may be useful here. Check out scale_color_brewer function for some discrete category color palette options.

4. Functional plotting with ggproto

Save your plot from part 3 as plot_ex3 and write a ggproto function geom_ball that

  1. takes in an x, y and color aesthetic and computes the median x and y values for each “group” assigned via the coloring. Do not compute a median for the missing group.

  2. find which point in the “group” has the farthest Euclidean distance from from the median coordinates.

  3. draw a circle for each group on the plot, using matching color scheme, centered at the median and with a radius that passes through the farthest point

Show the output of the code below:

plot_ex3 + 
 geom_ball()

Do any individuals fall into multiple plotted balls? If so, what do you think this might mean?

5. Reflect to match the map

Load the sf and rnaturalearth packages at the top of your qmd file. Next use the provided code below as a template to plot a map of part of Europe.

europe <- ne_countries(
  scale = "medium",
  returnclass = "sf"
)


p2 <- ggplot(europe) +
  geom_sf(fill = "grey95", color = "grey70") +
  coord_sf(
    xlim = c(-15, 45),
    ylim = c(35, 65)
  )
Hint

The coordinates in pop_locations are longitude and latitude measured in decimal degrees. When converting these coordinates to an sf object, for purposes of plotting, you will need to specify an appropriate coordinate reference system. Determine the EPSG code commonly used for standard longitude/latitude coordinates and supply it to st_as_sf(), e.g.

  pop_locations,
  coords = c("longitude", "latitude"),
  crs = ____
)

Display the plot side-by-side with your plot from exercise 3 using the patchwork package. Reflect the principal components and/or change the axes of your plot from exercise 4 so the two plots look similar. Make sure there are no redundant legends.

Style guidelines

All assignments in this course must employ proper coding style, as outlined below:

  • All code should obey the 80 character limit per line (i.e. no code should run off the page when rendering or require scrolling). To enable a vertical line in the RStudio IDE that helps guide this, see the style guidelines from lab 0 or ask a member of the teaching team for help.

  • All commas should be followed by a space.

  • All binary operators should be surrounded by space. For example x + y is appropriate. x+y is not.

  • All pipes %>% or |> as well as ggplot layers + should be followed by a new line.

  • You should be consistent with stylistic choices, e.g. only use 1 of = vs <- and %>% vs |>

  • Your name should be at the top (in the YAML) of each document under “author:”

  • All code chunks should be named (with names that don’t have spaces, e.g. ex-1, ex-2 etc.)

  • File names in your GitHub repo such as lab-x.qmd must not be changed and left as provided. Additionally, your repo must pass certain basic checks. The results of these checks are visible on GitHub via the badges at the top of your README and the actions tab. These are meant to give you feedback around the structure and reproducibility of your repository and assignment - they do not assess the correctness of your work. You should consider them a necessary but not sufficient condition when turning in your work - passing all of the checks simply means your have met a minimum standard of reproducibility for the assignment.

Fundamentally, the check is making sure 1) you only have the files you should in your repository, 2) your .qmd renders.

If you have any questions about style, please ask a member of the teaching team.
